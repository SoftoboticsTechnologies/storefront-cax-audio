# UI system

Current state of the design system in `apps/storefront` (audited 2026-08-31), plus target direction for the premium-ecommerce modernization. Update this file whenever a reusable UI convention is established — don't let pages invent divergent styles.

## Stack
- Tailwind v4 (CSS-based config, no `tailwind.config.js`). Tokens declared in `src/app/[locale]/globals.css` via `@theme inline` + `:root`/`.dark` (oklch color space).
- shadcn (`components.json`: style `base-vega`, baseColor `slate`, icons `lucide`), primitives in `src/components/ui/*`.

## Brand tokens (2026-09-23 — visual direction modeled on autodukan.com)
- Colors (`globals.css` `:root`/`.dark`): `--primary` = brand orange `#ff6633` (`oklch(0.698 0.197 38)`, same in both modes, white foreground); `--foreground` = deep navy ink `#0b1220`; `--muted` = cool gray `#f4f6fa` (image wells, input fills); `--accent` = orange tint (icon tiles, hover fills); `--ring` = orange. New `--navy` / `--navy-foreground` / `--navy-muted` (Tailwind `bg-navy`, `text-navy-foreground`, `bg-navy-muted`) for dark bands: announcement bar, editorial banner, "why us", footer. Dark mode background is the same navy.
- Radius: `--radius: 0.75rem`.
- Fonts (`site/locale-layout.tsx`, `next/font/google`): body `Barlow` (`--font-barlow` → `font-sans`); display `Bebas Neue` (`--font-bebas-neue`); Geist Mono kept for mono.
- Utilities: `font-display` (Bebas, uppercase, tight leading, weight reset — Bebas has one weight) for hero/section/card headings; `eyebrow` (small tracked orange uppercase label). Note `@theme inline` does not emit its vars at runtime, so custom `@utility` rules must reference the next/font variable directly.
- Contrast: white on `#ff6633` is ~3:1 — fine for bold button labels and large display text, not for small body copy. Don't use `text-primary` for small paragraph text.

## Section heading pattern
`components/ui/section-heading.tsx` → `SectionHeading({eyebrow, title, highlight, description, action, inverted})`: orange eyebrow → `font-display` title with the `highlight` words in orange → muted description → right-aligned action. `sectionActionClassName` is the outlined pill "View all →" link. Use this for every merchandising section (home + `ProductCarousel`) instead of ad-hoc `<h2>`s; pass `inverted` on `bg-navy`.

## Current navigation (`src/site/navigation/`)
Header (2026-09-23): in normal flow (was `fixed` + per-page `mt-16` offsets, which overlapped the announcement bar and cart/checkout content — offsets removed); **only the category bar is `sticky top-0`** (md+ only, hidden on mobile), rendered as a sibling of `<header>` because a sticky element can't outlive its parent's box. Two tiers: logo · wide pill search trigger (orange circular icon) · language/currency/theme/cart/user (signed-out "Sign in" is a primary button); then a category bar (orange "Shop all" pill + mega-menu). Nav/footer use `getRootCollections` (`features/collections/data.ts`) — roots derived from the existing query (collections not listed as anyone's child) — because `getTopCollections` returns every collection flattened.

`navbar.tsx` + `navbar/{navbar-collections,mobile-nav,mobile-nav-wrapper,mobile-search,navbar-cart,cart-icon,navbar-user,login-button,currency-picker(-wrapper),language-picker,theme-switcher,navigation-link,navbar-link,search-input,search-overlay}.tsx`.

Category bar (2026-09-24): full-tree dropdowns. `getCollectionTree` (`features/collections/data.ts`) rebuilds the whole Vendure collection tree from `getTopCollections` (each collection lists its direct children — no new query). `navbar-collections.tsx`: each top-level collection with children is a `NavigationMenuTrigger`/`Content` dropdown — first a bold `Navigation.viewAllIn` link to the parent (the trigger isn't a link), then the whole subtree flattened depth-first (`flattenCollectionTree`, `features/collections/collection-tree.ts` — Vendure-free so the client mobile nav can import it), deeper levels indented and muted. Leaf top-level collections stay plain links. `mobile-nav.tsx` mirrors this with one `Accordion` per parent. Names are `.trim()`med. Top-level order follows the collections list order from the Shop API, not the Admin drag order.

Search overlay (shipped 2026-08-31): `search-overlay.tsx` is a shared client component (`ui/command.tsx` inside `ui/dialog.tsx`) used by both desktop (`search-input.tsx`, now a trigger button) and mobile (`mobile-nav.tsx` search trigger — closes the sheet, then opens the overlay). Suggestions come from `features/search/suggest.ts`'s `getSearchSuggestions` server action, which reuses the existing `SearchProductsQuery` (`take: 6, groupByProduct: true`) — no new GraphQL operation. Debounced ~200ms via `useDeferredValue` + a `setTimeout`/`useTransition` pair. Enter with no suggestions falls through to `/search?q=`; selecting a suggestion navigates to `/product/[slug]`.

## Current homepage (`src/site/home/`)
Redesigned 2026-09-23 after autodukan.com: `AnnouncementBar` (navy) → `HeroSection` (full-width banner carousel — `hero-carousel.tsx` on the shadcn `Carousel`, slides in `hero-slides.ts` → `public/hero/*.webp` (Cax Audio brand → `/search`, then BMW, Mercedes-Benz, Audi, Porsche), 3.5 s loop autoplay paused on hover/focus and under reduced motion, arrows (md+ only, vw-sized) + dots over the image, per-slide caption band below it with copy in `Hero.slides.*`; each slide links to its make's collection by slug, else `/search?q=`; h1 is `sr-only` because the headline is baked into the artwork; `hero-finder.tsx` search-by-vehicle card kept unused for future use) → `TrustStrip` (4 cards: round icon, title + description, corner arcs; copy in `Home.trust`) → `CategoryDiscovery` (tile grid, top-level collections only via `getRootCollections` since 2026-09-24, image well + uppercase label; no Vendure image → slug-matched fallback photo from `features/collections/fallback-images.ts` (`public/categories/`, CC BY-SA, see `CREDITS.txt`), else a letter placeholder) → `FeaturedProducts()` (no slug = whole catalog via `SearchProductsQuery`, so it isn't empty when the first collection has no products) → `BrandGrid` (values of the facet whose code is `HOME_BRAND_FACET_CODE`, default `vehicle-brand`, overridable via `NEXT_PUBLIC_HOME_BRAND_FACET_CODE`; tiles show logo + name only (no product count / "Coming soon" line since 2026-09-24); shows every value that has products **or** a recognised make logo, so e.g. Mercedes-Benz appears before products are tagged; logos are Simple Icons CC0 SVGs in `public/brands/`, matched by name/code prefix in `site/home/brand-logos.ts` and drawn as a CSS mask — brand hex in light mode, foreground in dark) → `TrendingProducts` → `BenefitsSection` (navy "why us", numbered cards) → `EditorialBanner` (navy split banner, second root collection; photo from the slug-matched `BANNER_IMAGES` map (`public/banners/`, see `CREDITS.txt`) else the collection's featured asset; moved below "why us" 2026-09-23) → `CtaBanner` (orange band → `/register`). Brand data comes from `features/search/data.ts#getCatalogFacet`: all values via additive `FacetByCodeQuery`, merged with counts from additive `CatalogFacetValuesQuery` (`take: 0`). The finder and brand grid hide themselves when that facet doesn't exist. The reference's stats row (SKU/city counts, rating) was deliberately **not** reproduced — there's no real data behind it.

## Business contact & enquiries (2026-09-23)
Single source: `src/config/business.ts` (`BUSINESS` + `telHref`/`mailHref`/`whatsappHref`). Used by: announcement bar ("Call us" tel link), footer Contact column (replaced the Vendure GitHub/docs links) + "Contact Us" link, site-wide floating WhatsApp button (`site/whatsapp-button.tsx`, bottom-right, `#25D366`), `/contact` page (`site/contact/page.tsx`, route re-export in `app/[locale]/contact/page.tsx`), and `site/business-json-ld.tsx` (schema.org `AutoPartsStore`, mounted once in `locale-layout.tsx`). Enquiries go to **email/WhatsApp**: static export has no server to receive a form post, so `site/contact/enquiry-form.tsx` builds a pre-filled `wa.me` or `mailto:` link (submit button chosen via `SubmitEvent.submitter`) — nothing is stored or sent by the site. `components/whatsapp-icon.tsx` is the WhatsApp glyph (Simple Icons, CC0). Copy lives in the `Contact` namespace of `site/messages/*.json`.
